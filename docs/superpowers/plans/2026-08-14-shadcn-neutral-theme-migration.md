# Shadcn Neutral Theme Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Migrate the entire Next.js frontend to shadcn/ui's neutral CSS-variable theme system with first-class light and dark mode support.

**Architecture:** Initialize shadcn/ui in the existing `frontend` app, make `app/globals.css` the single source of truth for neutral theme tokens, and route all UI styling through semantic Tailwind utilities such as `bg-background`, `bg-card`, `text-foreground`, `text-muted-foreground`, `border-border`, `bg-primary`, and sidebar tokens. Add `next-themes` for light/dark/system mode, replace custom one-off UI pieces with shadcn-compatible primitives, and migrate existing pages in vertical slices so every screen remains buildable after each task.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript, Tailwind CSS v4, shadcn/ui CLI, shadcn neutral theme, next-themes, lucide-react, Vitest, React Testing Library.

---

## Scope And Current State

The frontend lives in `frontend/`. It is currently a Tailwind v4 Next.js app with no `components.json`, so shadcn/ui has not been initialized yet. The existing design system is hand-coded in `frontend/app/globals.css` and many components use direct dark colors like `bg-[#111726]`, `border-[#1e293b]`, `text-slate-100`, and `text-indigo-400`.

The migration is complete when:

- `frontend/components.json` exists and declares shadcn with `baseColor: "neutral"` and CSS variables enabled.
- `frontend/app/globals.css` defines shadcn neutral tokens for `:root` and `.dark`, plus Tailwind v4 `@theme inline` mappings.
- `frontend/app/layout.tsx` wraps the app in a shadcn-compatible theme provider using `next-themes`.
- The dashboard has a visible light/dark/system mode toggle built with shadcn primitives.
- Existing screens no longer depend on raw slate/indigo hex theme utilities for layout, cards, forms, buttons, navigation, or page shells.
- Domain event colors remain available through explicit semantic tokens for workflow execution events.
- `npm run lint`, `npm run build`, and the new theme tests pass.
- Manual browser checks confirm light mode, dark mode, and system mode are usable.
